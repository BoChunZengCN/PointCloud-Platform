独立只读复审指出 4 项重要缺口，已按单轮修复边界处理：准备运行在活动指针或最终清单写入失败时不得留下可激活的 ready 版本；固定查看器所需的属性字段、坐标元数据和可达层级子节点必须在发布前校验；转换器执行文件与查看器脚本须匹配固定指纹，并在新发布清单记录目标版本；本机展示页须显示真实已发布资产而非 `site-a-las` 演示回退。各项均有先失败、后通过的回归。真实完整产物在加强的校验下仍得到 47,899,752 点与 RGB；无需再次转换原始 LAS。

## 验证状态与边界

修复后的聚焦门禁覆盖来源、转换、发布、命令、服务、展示页、旧小文件预览和真实 Chromium，共 **67 项通过**；小文件 JavaScript 单测 **8 项通过**，两个展示脚本语法检查和 `git diff --check` 通过。

最初将 `tests/browser` 与后端测试放在同一 Python 进程、并使用较长的 `--basetemp` 路径时，得到 1504 通过、3 跳过、12 失败。后续定位证明该调用不等同于 CI 门禁：其中 11 项 Phase 15D/E 失败的底层异常是 Windows 在过长路径中创建特征临时文件时返回 `FileNotFoundError`，同一用例改用短临时目录即通过；另 1 项 Phase 15A 的 `asyncio.run()` 在先运行 Playwright 测试后遇到残留事件循环状态，干净 `main` 上也可复现。上述现象不是点云预览生产逻辑的失败，亦不通过降低索引覆盖率门槛来掩盖。

按仓库 CI 的分进程边界重新完整验证：**后端 1502 通过、3 跳过；Chromium 浏览器 28 通过**。Windows 本机复现时，后端与浏览器应分别运行，并给 `--basetemp` 指定项目 `workspace/` 内的**专用、短、可清空**目录（pytest 会清空该目录），不要把真实数据目录作为测试临时目录。此结论只适用于已验证的当前提交；推送后的远端 CI 结果仍需单独确认。

当前功能只验证未压缩 RGB LAS 1.2/1.3 点格式 2/3 的本机分层预览；LAZ、其他输入格式、远程共享、语义分割、Mesh 和 CAD 仍不在此轮范围。第三方资源与真实点云/产物位于 Git 忽略的 `workspace/`，不进入仓库提交。本阶段尚未推送或合并。
