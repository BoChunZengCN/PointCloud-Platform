# 点云平台产品方向与后续开发路线

记录日期：2026-10-15
状态：讨论结论与后续开发方向；不代表功能已实现、架构已批准或生产性能已验证。

状态补充（2026-10-21）：点云转网格路线的第一层 Mesh 能力已完成第一里程碑 Task 1–7，Task 8 集成验证、中文操作说明与发布门禁尚未完成；第二层 B-rep/CAD 曲面拟合、拓扑重建、实体生成和 STEP 输出仍未实现。其余方向继续按本文路线推进。

## 一、背景与目标

开发者为个人开发者。结合 Prevu3D 产品研究及现有 point-cloud-system 的资料和部分代码检查，保留现有平台作为基础，探索面向工程人员的点云在线使用、模型生成与第三方交付能力。

用户明确提出后续四个开发方向：

1. 点云在线预览（pointcloud online preview）。
2. 点云转网格（pointcloud to mesh）。
3. 通过模型数据库匹配，将点云对象关联并对齐到已有三维 CAD 模型（pointcloud to 3d CAD by matching model database）。
4. 点云逆向重建边界表示模型（pointcloud to reverse convert B-rep model）。

当前任务仅记录方向，后续逐项形成设计、实现计划和验收数据集。

## 二、共同产品原则

- 点云本身即可用于远程踏勘、标注、测量、截面、变化分析和设计对照，不必先变成 Mesh 或 CAD。
- 点云、Mesh、CAD 是不同用途的数据表达，不是必须依次完成的升级链。
- 点云作为现场观测与追溯依据；对象身份、人工确认和任务结果作为平台业务组织中心。
- 根据用户任务按需生成 Mesh、匹配已有 CAD 或重建 B-rep，保留源数据、坐标、单位、变换和版本关系。
- 商业价值来自下游任务：减少人工建模、数据整理、重复踏勘和返工，满足设计、修改、制造或交付要求。
- 漂亮的显示、格式转换成功、检索高分或配准通过，均不能单独证明工程正确性。
- 缺失扫描区域属于未知区域，不能直接认定为空闲空间；网格补面和几何推断必须与观测数据区分。

## 三、四条开发路线

### 路线一：点云在线预览

目标：用户无需安装重型桌面软件，即可查看真实点云、定位和理解现场，作为其余路线共同入口。

建议首版：已配准 LAS/LAZ 接入、按层级或空间范围流式加载、基本导航、裁剪、测量、对象选择及属性展示。既有 Potree 发布及查看器入口可复用，但需验证实际渲染和对象交互闭环。

商业场景：远程踏勘、项目复核、现场尺寸查询、扫描成果交付。

验收重点：真实数据加载正确；单位和坐标正确；首屏时间、交互帧率、浏览器内存和网络量可测；无静默演示数据回退；测量用途和限制明确。数值目标待选定设备与数据集后制定。

### 路线二：点云转 Mesh

目标：生成可被第三方设计、布局或可视化软件使用的实景参考资产。

建议首版：局部区域或单对象选择、预处理、法线处理、网格重建、清理、轻量化、点云叠加复核、导出。颜色传递和影像纹理映射是不同能力，不默认仅凭有色点云即可生成高质量纹理。

商业场景：减少人工重建外形；设备布局资产；扫描成果轻量交付；下游需要连续表面的操作。

验收重点：几何偏差、关键细节保留、错误补面、面数和文件体积、处理资源及人工修补时间；必须在选定目标软件中验证导入。

边界：网格不自动具备零件参数、工程语义、可制造性或 CAD 特征树。

### 路线三：模型数据库匹配与 CAD 对齐

目标：对分割对象检索已有模型，由配准和人工确认形成对象—模型—姿态绑定，复用标准模型。

流程：点云对象 → 人工纠正 → 候选检索 → 刚性配准 → 质量判断 → 人工确认 → 场景组装与交付。

商业场景：重复设备资产整理、已有设备模型复用、工厂改造和布局准备。

现有基础：模型版本、采样、特征索引、候选检索、Open3D 配准及人工绑定已有对应模块；当前检查未重新运行真实数据验收。

验收重点：候选正确率、无匹配判断、遮挡及对称歧义、姿态精度、人工确认工时、组装结果及目标软件可用性。

关键边界：现有模型库导入以 STL/OBJ/PLY 网格为主。匹配网格不能凭空产生原生 CAD/B-rep。如果承诺输出工程 CAD，模型库必须另外保有经授权、可用的工程模型源文件及对应版本、单位和映射。外形相似和配准通过不证明型号、接口或内部结构一致。

### 路线四：点云逆向重建 B-rep

目标：在没有合适已有模型时，从观测几何重建可用于工程操作的曲面或实体边界表示。

建议从单对象、简单几何开始：平面、圆柱、圆锥等拟合，边界与交线求解，曲面裁剪，拓扑构建、缝合与合法性检查，人工修正及导出。复杂自由曲面和装配结构另行评估。

商业场景：缺图零件逆向、局部改造、恢复可修改的工程几何。

验收重点：与观测点云的偏差、拓扑有效性、预期实体的闭合性、下游 CAD 内核导入及实际编辑操作；工程用途另需工程师复核。

关键边界：B-rep 不等于完整参数化特征树或设计意图恢复；把三角面封装成 STEP 不算实现工程逆向建模。需要时可直接从点云拟合几何，不强制经过 Mesh。只重建扫描到的表面不能自动恢复内部及被遮挡结构。

## 四、平台与云端部署方向

讨论倾向：平台统一管理项目、数据、对象、任务、复核、版本和交付，重计算交给后台 Worker。云端适合受控试点，尚不认定现有系统已具备公共多租户 SaaS 能力。

建议逻辑结构：浏览器 → 平台 API → 项目与任务数据库 / 对象存储 → 任务队列 → 计算 Worker。

可保留现有领域逻辑和不可变工件；本地工作区可作为任务暂存空间。逐步明确数据库与文件工件的职责，不能直接将本地文件锁和 JSON 状态等同于分布式并发控制。

云端待补充：大文件分片及断点续传、校验、项目权限和下载授权、真实后台调度、超时/取消/重试、并发及资源上限、任务费用记录、存储生命周期和备份。

代码检查发现：job_runner.py 的 execute_job_steps 是模拟状态推进，JSONL 队列为预留；部分外部工具具有真实调用边界。需要统一真实计算执行与产物确认，不以状态 completed 代替结果验证。

初期控制单个或少量任务并发，无需提前建设复杂微服务或集群。GPU 是否必要由算法和实测决定。Worker 接口可保留未来客户本地部署能力，不要求首版同时实现云端与本地两套产品。

## 五、建议实施顺序与复用

四条方向并非必须顺序串行：

- 在线预览是共同基础，应优先形成真实可交互入口。
- Mesh 路线作为新增处理能力，可先从单对象闭环验证。
- 模型匹配路线已有较多基础，可同步收敛为一个实际交付场景，补充源 CAD 资产条件及导出。
- B-rep 先做限定几何的可行性验证，再决定生产实现范围。

已有质检、分割纠正、模型库、检索配准、人工绑定、审计与交付机制按需复用。优先实现用户能完成的工作，不以继续增加阶段数量作为进展标准。自动训练、广泛格式支持和 3DGS 不作为四条路线首版的必要前置条件。

## 六、商业验证与待决策事项

用至少三个独立真实项目记录处理成功率、输入规模、算力与存储流量成本、人工修补工时、下游使用结果及付费意愿。具体数量是验证建议，不是已确认合同或市场证据。

商业判断：客户节省的人工、复测和返工成本，以及新增可完成的业务，应覆盖处理、复核、支持和维护成本。

实施前待确定：

1. 首个客户类型及付费任务。
2. 首个目标第三方软件、版本、格式和必须支持的操作。
3. 首版输入数据、规模、设备和性能预算。
4. 工程精度及人工复核要求。
5. CAD 模型源文件、知识产权及可交付授权。
6. B-rep 首批支持的几何类别和几何内核。
7. 云端上传接受程度、数据隔离要求和任务收费方式。
