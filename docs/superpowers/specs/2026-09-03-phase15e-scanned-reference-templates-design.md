# Phase 15E：实物参考点云模板设计规格

**日期：** 2026-09-03

**状态：** 用户于 2026-09-03 授权按本规格进入开发；实施前进行持久化设计复审。不是功能完成声明。

**代码基线：** `main`，`5385ade`（Phase 15D 已通过 PR #9 合并）。

## 1. 已确认的边界

- 没有 CAD 的实物扫描点云可以独立成为参考资产，并具备版本、发布、回滚、检索、刚性配准和人工绑定能力。
- 复用统一模型资产体系，明确区分 `scanned_reference` 与 `cad_sampled`；不另建一套独立模板库。
- 导入不等于发布，未经质量检查和人工确认的模板不得进入生产检索。
- 模板、发布和绑定历史不可覆盖；新模板版本不能自动替换已存在的对象绑定。
- 本阶段新增扫描参考模板模式。现有 CAD 导入、采样、检索与绑定继续兼容，但新增的 CAD 关联、同资产双表达切换和坐标对齐留到后续阶段。
- 扫描模板不是 CAD，不生成虚构网格，不承诺自动逆向建模、精确尺寸真值或工程安全认证。

第 2 节起为本次开发采用的详细设计。数值为首版工程限制而非性能实测；任何实质性架构或威胁边界调整仍需另行确认。

## 2. 目标与范围

### 2.1 交付目标

一份已经裁剪、清理的单对象参考点云可以完成：

`导入 → 自动检查 → 专家核验 → 发布模板 → 构建并启用索引 → 检索与刚性配准 → 人工确认 → 可追溯绑定`

既支持全新扫描参考资产，也支持该扫描参考资产的新版本；不要求存在任何 CAD 文件。

### 2.2 本阶段包含

- 受控单文件导入、原始文件留存、单位转换和确定性匹配点集生成。
- 自动质量报告、专家通过或拒绝核验、版本历史、发布与回滚。
- 统一表达读取接口，接入现有特征、索引、检索、配准和 Phase 15D 决策链。
- 专业管理页面、API、CLI，以及业务候选上的来源类型展示。
- 权限、并发、幂等恢复、审计、旧 CAD 数据兼容和真实浏览器验收。

### 2.3 明确不做

- 不在导入过程中自动分割整场景、拼接多个扫描、修补缺失表面或执行自动去噪。
- 不新增通用上传服务、远程 URL 下载、压缩包导入、FLS/E57 原始扫描解码。
- 不新增 CAD 关联、双表达配准、网格重建、CAD 导出或已有 CAD 功能重写。
- 不实现统一三维查看器、设备生命周期管理、自动训练、参数自动推广。
- 不新增多人审批链、跨用户接管恢复、批量删除或自动清理历史工件。

## 3. 现状与架构选择

### 3.1 现有代码的实际约束

- `model_import.py` 的版本清单与几何校验面向网格；仅添加文件扩展名不能支持扫描版本。
- `model_sampling.py`、`model_feature_store.py`、`model_feature_index.py`、`model_registration_input.py` 多处固定读取 `cad_sampled`。
- 特征配置的采样算法固定为网格面积采样；扫描点集需要独立、可复现的选点策略。
- 模型发布与特征索引发布已经是不同操作；本阶段不把它们伪装成一个跨模块事务。
- Phase 15D 的绑定已经固定模型版本、表达、配准报告与刚性矩阵，适合作为扫描绑定的下游。

### 3.2 采用的方案

采用“统一资产与生命周期、按来源分派读取和生成”的方式。新增扫描专用解析、质量与核验模块；上游生产不同来源的匹配点集，下游共享特征、检索、配准和决策。

独立建扫描库会重复发布、权限与审计；将扫描点云伪装成 CAD 网格会破坏来源和几何语义，均不采用。

只抽取本阶段实际需要的版本与表达入口，不对审计账本、全部文件系统工具或全部模型库进行顺带重构。

## 4. 数据输入与坐标约定

### 4.1 首版输入

支持 LAS、经过验证的 LAZ 子集和点式 PLY（用户确认收窄首版 LAZ 范围）：

- LAS/LAZ：读取 XYZ；RGB、强度、分类等原始属性保留在源文件中，不作为本阶段匹配必要条件。LAZ 解码能力缺失时明确报错，不降级为模拟读取。
- LAZ 首版限定 LAS 1.4 点格式 6/7/8、固定分层压缩、标准第 3 版点项、无附加字节且具备直接块表指针。逐块核对独立点数、层字节总数、块表边界和文件头总点数。旧式固定块、变长块、波形/附加字节或 EOF 回填表指针等未验证变体返回 `reference_laz_variant_unsupported`，提示先转换为 LAS；不宣称支持所有合法 LAZ。
- PLY：支持 ASCII 和二进制大小端的标量顶点属性，必须存在 XYZ。带非空面数据的网格及列表型顶点属性不走扫描入口，应提示使用合适的输入流程。
- 原始文件、实际格式、读取器名称及版本、原始字节指纹必须记录。格式签名、声明点数和实际解码结果须一致。
- API 和页面使用项目内受控暂存区的文件标识，延续现有 `staged_source` 模式；不接受任意服务器绝对路径或 URL。CLI 可以显式指定本机普通文件，由导入服务复制并冻结。
- 本期不直接从分割对象“自动晋升模板”。可以导出已审查对象后导入，并记录来源；源对象改变不应改变已导入模板。

### 4.2 默认资源限制

首版默认限制：单个原始文件 128 MiB、解码点数 1,000,000、单次导入总工件 512 MiB、累计保留导入工件 2 GiB、最多两个并行解码工作进程。部署可以调低，但不得由普通 API 请求调高。

使用受限工作进程解析，单次解码与标准化总时限 120 秒，超时终止该解析进程并记录失败。检查声明点数，也在实际解码时计数，不能仅依赖文件头。受控暂存区、进行中的导入和失败保留文件计入配额。

这些数值是首版工程保护值，不代表已测得的吞吐或最大生产容量；真实数据基准在验收报告中记录。

### 4.3 单位、原点和精度

- 用户必须声明 `mm`、`cm` 或 `m`，内部几何统一为米。单位换算只发生在导入，不属于允许配准缩放。
- LAS 的存储 scale/offset 用于恢复原坐标，之后只执行一次声明单位到米的换算，不重复应用存储比例。
- 明确的文件单位信息与声明冲突时阻止导入；地理经纬度坐标不能直接当作线性米坐标使用。本阶段不进行地图投影变换。
- 标准化点集以换算后包围盒中心为局部原点，轴向保持不变，不用 PCA 自动旋转，也不缩放到单位包围盒。
- 保存局部原点、单位比例、坐标处理算法版本和 `source_m_to_reference_4x4`。该矩阵只描述米制源坐标到模板局部坐标的平移。
- 配准矩阵方向固定为“模板局部米制坐标 → 目标对象米制坐标”；历史绑定不得误用原始大坐标。
- 原始数据不被量化覆盖；派生 JSON 坐标使用统一的 12 位小数规则，若数值溢出、非有限值或量化后几何退化则拒绝。

## 5. 自动质量检查与专家核验

### 5.1 自动检查不等于准确率认证

自动检查回答“输入是否有效、能否进入匹配流程、有哪些风险”，不能证明点云完全无噪声、扫描完整或型号标注正确。

质量报告固定源文件与标准化点集指纹，记录输入/唯一点数、重复比例、局部尺寸、点间距统计和几何退化指标。报告以完整解析后的点集进行计数和边界统计；昂贵的点间距统计最多使用 4,096 个确定性选点，并显式标注估计值。

首版质量策略 `scan-quality-v1`：

- **硬失败 `rejected`：** 文件/属性损坏、缺 XYZ、非有限坐标、单位冲突、不支持的坐标系、资源超限、标准化后唯一点少于 64、零跨度或近共线几何。
- 协方差特征值按 `lambda1 >= lambda2 >= lambda3 >= 0` 排序。近共线判据采用 `lambda2 / lambda1 <= 1e-8`；零方差直接拒绝。此阈值仅为几何可用性规则。
- **风险 `review_required`：** 重复点比例至少 20%，或 `lambda3 / lambda1 <= 1e-8` 的近似平面数据；不因此自动补点或修改形状。
- **自动检查通过 `passed`：** 无上述问题。依然需要专家核验，并非自动发布许可。

重复点在派生计算集内按标准化坐标去重，源文件原样留存；不根据 RGB 或强度制造重复几何。质量策略版本、阈值、工具版本和报告指纹被冻结。重新清理、修改单位或换质量策略产生新版本，不替换原报告。

### 5.2 人工核验

沿用 `expert` 权限，不新增角色。专家确认三件事：

1. 数据对应单个目标对象，背景与明显污染已处理。
2. 型号/类别、来源、使用许可和单位记录可信。
3. 可见表面足以用于本次参考匹配；对扫描缺失与噪声的局限已知悉。

专家提交 `approved` 或 `rejected`、原因，以及已确认的风险码。存在自动硬失败时不能人工强行通过。对风险项不要求冗长逐项说明，但必须明确勾选已知悉。

每个版本只允许一个不可变最终核验记录；同操作重试返回相同记录。拒绝后修订产生新版本，首版不提供在同一版本上反复改票的审批系统。专家可核验自己导入的数据，不引入双人独立审批要求。

## 6. 资产、版本和表达契约

### 6.1 资产身份

扫描资产复用 `models/{model_id}` 和现有名称、类别、厂商、型号、关键词、标签。

新增扫描资产清单使用 `schema_version: "1.1"`，显式记录 `source_family: "scanned_reference"`；旧 `1.0` 资产按 CAD 来源解释且不重写。新建接口省略来源仍走现有 CAD 行为。

首版扫描资产仅接受扫描版本，CAD 资产仅接受原有 CAD 版本；服务端两侧入口都要检查，不能只靠页面隐藏。未来同资产多表达由后续规格升级此约束，本阶段不预建关联关系或假 CAD 版本。

### 6.2 扫描版本

版本继续位于 `models/{model_id}/versions/{version_id}`，扫描版本清单使用 `schema_version: "2.0"`、`source_kind: "scanned_reference"`。

清单至少固定以下内容：

- 身份：`model_id`、`version_id`、`supersedes_version_id`、操作及导入者身份。
- 来源：格式、原始文件相对路径、指纹、读取器及版本。
- 元数据：类别/型号来源说明、许可证或使用授权说明、扫描来源、裁剪与清理过程；未知扫描时间可以为空，不能伪造。
- 几何：声明单位、换算比例、局部原点、坐标矩阵、输入点数与唯一点数、原始和标准化尺寸。
- 工件：原始文件、标准化唯一点集、自动质量报告及各自指纹。
- 策略：标准化算法、质量配置与指纹、资源限制快照。

版本一经完整导入即不可变。解析硬失败不公开为有效版本；能形成完整质量报告但不满足准入的数据允许在专业清单中显示“检查不通过”，不能成为发布目标。

### 6.3 匹配表达

匹配表达位于 `models/{model_id}/representations/{version_id}/scanned_reference/{representation_id}`。包含 `representation.json` 与米制局部 `sampled_points.json`，并固定源版本、质量报告、生成配置及几何指纹。

新增统一读取入口返回类型、点集、坐标约定和证据；未知来源或缺失声明报完整性错误，不能依靠“哪个目录恰好存在”猜测。

扫描选点算法 `sha256_point_subset_v1`：对标准化唯一 XYZ 的规范字节与种子求 SHA-256，按哈希及 XYZ 稳定排序，取配置指定数量；输出再按 XYZ 排序。选点只能取自实测点集，不插值、不复制点凑数。可用点少于目标数量时全部保留；少于所选特征或配准配置的最小点数时明确拒绝。

特征配置新增 `1.1` 版本，保留原 CAD `sampling`，增加独立 `scanned_sampling`（算法、点数、种子）。旧 `1.0` 配置继续按旧 CAD 行为执行；遇到扫描来源时报配置不支持，不能擅自补默认配置或静默排除。

## 7. 发布、索引和回滚

### 7.1 模板发布

沿用 `expert` 发布与回滚权限。扫描版本发布必须验证：完整导入、无自动硬失败、专家已通过、源与质量工件指纹未改变。

核验记录独立保存，包含版本清单和质量报告指纹；不能追加字段修改已经发布的版本清单。扫描发布记录使用新 `1.1` 契约固定核验记录及其指纹，旧 CAD 发布 `1.0` 原样保留。

沿用 `expected_current_release_id` 并发规则：第一次发布以空值表达无当前版本，后续必须匹配当前头；冲突刷新后重新决策，不强制覆盖。

### 7.2 生效状态不能混淆

页面分别显示：

- 检查状态：通过、存在风险、检查不通过。
- 核验状态：待核验、已通过、已拒绝。
- 模板发布状态：未发布、当前发布、历史发布。
- 检索状态：未进入当前索引、已进入当前有效索引、索引需要更新。

发布模板不会自动启用新索引。复用现有生产索引构建与发布动作；页面提供下一步入口和明确结果。任一步失败不撤销已成功的上一步，也不能展示整条链已成功。

生产索引只收录已核验的当前发布扫描版本；Challenger 可以显式选择已核验的历史发布，不绕过核验。构建时遇到损坏、配置不兼容或无法生成特征的来源，必须报告原因并遵守现有索引覆盖率门禁，不静默丢弃。

### 7.3 回滚

模板回滚生成新的发布记录，指向同一资产已有、已核验的历史版本。禁止覆盖版本文件或回退审计记录。

模板回滚与索引回滚是不同动作；旧索引若不满足现有当前发布头校验，必须重建/发布匹配的索引，不能只改“当前版本”指针绕过检查。

任何发布或回滚均不重绑已有场景对象；旧绑定继续引用原版本和原位姿。重新匹配及替换绑定沿用 Phase 15D 的专家操作。

## 8. 检索、配准和绑定兼容

- 特征算法和评分含义保持不变；仅新增扫描表达的读取、选点和证据适配。扫描与 CAD 的特征分数不是经过标定的识别概率。
- 新的混合来源索引条目/清单与模型特征清单使用 `1.1`，固定 `representation_type`。CAD 与扫描属于不同资产时可出现在同一索引；本期不进行同一资产的双表达择优。
- 新检索候选与报告使用 `1.2`，固定表达类型及已有的精确版本、发布、表达和特征指纹。合法旧 `1.0`、`1.1` 报告继续按原契约读取。
- 新配准报告使用 `1.1`，固定候选表达类型与坐标约定；原 `1.0` 报告继续可读。旧 CAD 报告的来源只能由其受验证的历史证据解释，不回写原工件。
- 表达类型必须沿候选、输入、配准报告一致传播。不能让扫描候选调用网格采样，也不能缺字段时默认把新工件当成 CAD。
- 保持旋转和平移的刚性配准；不允许缩放、反射、错切或形变。低覆盖、缺失表面与对称歧义沿用现有门禁，不为提高“通过率”降低阈值。
- 扫描残差是与所用参考点集的比较，不代表与真实物体完整表面的精确误差，也不代表安装或碰撞安全。
- Phase 15D 的确认权限、拒绝/无匹配、对象陈旧检测和不可变绑定链保持不变。绑定 `1.0` 字段足以固定准确表达及报告；类型通过已验证报告解析，不增加第二套绑定文件。
- 模板核验与场景匹配决定不是同一件事。核验通过不等于所有匹配自动确认，身份确认也不提升为 `expert_pose` 真值。

## 9. 并发、持久化和威胁边界

### 9.1 信任模型

请求、元数据和上传文件均不可信；生产身份来自已有配置绑定，客户端不能自报角色。项目存储由服务账号控制，外部调用者不能直接改写模型库。

拒绝路径穿越、绝对暂存路径、符号链接/重解析点、特殊文件和远程来源。解析器在受限进程中运行，不执行文件所携带的脚本。支持单机本地文件系统，不承诺网络共享盘、多主节点或恶意本机管理员下的事务隔离。

这里的受限进程指计数、配额、并发和超时控制，不等同于操作系统安全沙箱。不能据此宣称隔离了解码依赖的任意代码执行漏洞；公开互联网的不可信上传服务及其沙箱架构不在本阶段范围内。

### 9.2 发布与恢复不变量

- 先冻结请求、源内容和操作身份，再生成派生工件；不能在重试时重新读取已经变化的外部源文件并当成原请求。
- 新扫描导入与核验使用所有者记录、不可变工件和最后发布的提交清单；正式读取需同时验证完整提交及审计完成证据。
- 同一版本的导入/核验按现有内核锁工具串行提交，不设置跨页面长期占用锁。发布沿用已有模型发布锁及冲突检测。
- 锁覆盖证据检查、文件发布与审计完成。第一提交者确定结果，其他操作不得接管其未完成的所有者。
- 响应丢失时，完全相同的操作三元组和请求指纹重放；请求内容不同则冲突，不能自动生成新操作覆盖。
- 已有所有者或提交状态不确定时保留可恢复状态，只允许原操作恢复。只有在锁内证明没有已发布结果或需恢复的所有者后，才能记录普通失败终态。
- 失败前后的临时与恢复工件保留并计入配额，不引入自动递归删除、目录搬移隔离或新的路径恢复框架。
- 不改写 Phase 15A 审计架构，不假装版本发布和索引发布具有跨模块原子性。实现若不能复用既有原语满足这些不变量，停止编码并请求架构确认。

### 9.3 审计内容

导入、解析/校验、派生选点、核验、发布/回滚、索引构建/启用及匹配操作记录操作身份、调用者、输入输出指纹、配置版本、时间、结果及稳定原因码。

技术拒绝进入审计；身份尚不可解析时使用现有边界拒绝记录，不捏造领域所有者。日志不记录令牌、原始点坐标全集或用户文件内容。页面仅向授权人员展示详细来源和核验说明。

## 10. 页面、API 与 CLI

### 10.1 简洁管理页面

从现有专业工作台进入“扫描参考模板”，提供全部、待核验、可发布、已发布、未通过的筛选清单，以及当前索引状态。

用户主流程分为三步：选择暂存文件并填写来源；查看自动报告和预览后核验；发布并按提示更新索引。业务人员只在候选和绑定详情看到“扫描参考”标识、名称、版本及匹配结果。

详情包含三个正交投影的轻量点云预览、米制尺寸、点数、风险、来源、版本及发布历史。预览使用至多 4,096 个确定性实测点，标注为辅助查看，不承诺通过投影证明对象完整；本阶段不引入完整三维编辑器。

清单查询只读，不产生核验副作用。提交期间禁用重复按钮，显示明确进度；冲突提示刷新；响应不确定时保留原操作请求供重试。令牌仅在内存中使用，元数据按文本渲染。

### 10.2 接口边界

建议新增扫描专用接口，避免让原 CAD 导入端点按文件后缀猜测语义：

- `POST /model-library/models/{model_id}/scanned-versions`：从受控暂存文件导入。
- `GET /model-library/models/{model_id}/scanned-versions`：分页查询扫描版本与状态。
- `GET /model-library/models/{model_id}/scanned-versions/{version_id}`：读取质量、预览及核验证据。
- `POST /model-library/models/{model_id}/scanned-versions/{version_id}/review`：提交一次最终核验。
- 发布、回滚、索引及匹配复用现有端点，不新增一键静默发布接口。

写操作仅允许 `expert`；`auditor` 只读专业证据；`operator` 只读取业务安全摘要。新扫描工件不得经现有公开模型元数据接口泄露完整源路径、许可正文或核验说明；只对新类型做必要响应裁剪，不顺带改变旧 CAD 公共接口的既有约定。

CLI 增加 `model-reference-import`、`model-reference-list`、`model-reference-show`、`model-reference-review`，调用与 API 相同的领域服务。发布/回滚沿用现有命令，不复制算法或恢复逻辑。

新增稳定错误码覆盖格式/读取器不可用、坐标或单位不支持、输入超限、质量不通过、核验冲突、核验未通过、来源类型不兼容；与已有 `permission_denied`、`operation_busy`、发布冲突和完整性错误统一映射。用户界面提供中文解释和下一步动作。

## 12. 验收标准

1. **独立扫描资产：** 没有 CAD 时完成创建、导入、核验、发布、检索、配准和人工绑定；不生成网格占位物。
2. **真实格式：** 使用实际 LAS、LAZ、ASCII PLY 和二进制 PLY 文件验证读取；覆盖无 RGB、截断文件、假点数、错误类型、解码依赖缺失和超限。
3. **坐标与确定性：** 同内容/单位/配置重复生成相同几何与特征指纹；点顺序或无关属性变化不改变 XYZ 派生结果；源文件指纹允许不同。覆盖 mm/cm/m、大坐标、非有限值、单位冲突和单次比例换算。
4. **质量不越权：** 硬失败无法强行通过；检查通过仍需专家核验；风险提示完整；同版本拒绝后不能改票覆盖。
5. **发布与索引：** 未核验数据不进入生产或 Challenger；模型发布后未更新索引时页面准确提示；旧配置遇到扫描数据明确失败而非静默忽略。
6. **回滚与历史：** 发布、回滚均追加历史；索引状态与发布头一致；历史配准和绑定可重建，原绑定不随模板变化而漂移。
7. **并发与恢复：** 双核验、双发布、相同请求重放、不同请求复用操作身份、复制/派生/提交/审计各关键中断点均有测试；不确定状态不错误终结或被接管。
8. **权限与页面：** 专家导入及核验、审计员只读、业务来源展示、公开接口裁剪、冲突刷新和响应丢失重试均由真实浏览器与 API 测试验证。
9. **旧系统兼容：** 历史 CAD 清单、配置、索引、候选、报告、发布和绑定继续读取；CAD 导入/采样正常；未修改原始历史文件。
10. **实际效果：** 至少一组独立重复扫描的正例和一组相似但不同型号负例，记录 Top-K、双向残差、覆盖率与人工结果。不能用同一文件复制出“独立扫描”或宣称泛化准确率；真实样本缺失时标注未完成真实数据验收。

验证顺序：直接回归 → 模块/聚焦集成 → 一次阶段全仓门禁 → 必要的发布前检查。文档草案阶段不运行全仓测试。实施最终复审只报告严重/重要问题、证据和提交 SHA；同类问题超过两轮按项目协议升级架构评估。

## 13. 后续 CAD 模式与已知限制

后续 CAD 模式需要单独定义同一资产多表达的版本关系、扫描到 CAD 的坐标变换、表达择优与去重、绑定语义及历史升级，不能只增加一个切换按钮。

本阶段保留来源类型、精确版本和坐标证据作为扩展基础，不提前建立不可验证的关联。扫描不完整、密度差异和噪声会影响现有几何特征及双向覆盖率；本阶段输出证据和拒绝理由，不通过自动放宽阈值掩盖问题。

Phase 15F 的受控参数优化、Phase 16 的统一查看器、Phase 17 的受控自学习仍为独立阶段。实施任务与验证证据记录在同日期的 Phase 15E 实施计划中。
