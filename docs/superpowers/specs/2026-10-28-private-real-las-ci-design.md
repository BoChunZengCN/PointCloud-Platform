# 私有真实 LAS 样本持续集成设计（2026-10-28）

## 目标与现状

用户允许使用机电房 `Filtered_points(1).las` 做真实验收，但不允许把原始数据放入公开的 PointCloud-Platform 仓库供所有人下载。目标是让 GitHub Actions 确实读取这份真实 LAS，完成平台现有的完整转换与浏览器预览验收，不再把资源缺失造成的 `skip` 视为通过。

本地已只读核验：LAS 1.2、RGB 点格式 2、218,266,379 字节、8,394,852 点，SHA-256 为 `ee1ac0dc4f49f9634d803d4a62313fda903d4d07d08dc86c5bd4afd040bffb69`。全部点分类值均为 0，因此它可以验证真实点云处理链路，但不能充当管线/设备分割准确率真值。本机运行 `prepare-full-preview` 已生成 8,394,852 点的 Potree2 产物；当前执行环境阻止本地 HTTP 客户端连接，故新样本的浏览器加载尚未通过验收。

现有 `.github/workflows/test.yml` 在 PR 和 push 上运行 Ubuntu 后端及浏览器检查；`tests/browser/test_full_preview_browser.py` 在固定本地资源不存在时会 `skip`。`full_preview_dependencies.py` 固定 PotreeConverter 2.1.1 **Windows** 可执行文件 SHA-256，故本次真实转换作业采用 GitHub 托管 Windows 运行器，不修改转换器信任模型。

## 方案比较与选择

1. **采用：独立 GitHub 私有仓库的 Release 附件。** 私有仓库只存放版本化真实样本附件，公开源码仓库仅持有附件标识、预期大小和 SHA-256；受控 CI 以限定该私有仓库的只读凭据下载。无需新开第三方云账户，数据仍托管在 GitHub，但不公开下载。
2. 新开私有对象存储。数据可离开 GitHub，但当前没有账户和存储配置；会增加账户、权限、计费和运维工作，本轮不选。
3. 本机单独测试。无需上传，却无法实现 GitHub CI 实际读取样本，本轮不选。

用户已选择方案 1。**独立私有仓库不是公开仓库的子目录**；不得把 LAS、转换后的二进制、截图或浏览器 trace 提交、发布或上传到公开仓库的任何附件。

## 范围与非目标

本轮交付：建立独立私有样本仓库和固定 Release 附件；在公开仓库增加专用的受控 Windows CI 作业及真实样本浏览器测试；提供中文配置、凭据轮换、手动触发与故障排查说明；以远端 Actions 成功且测试未跳过作为最终验收。

允许修改的公开仓库文件：新增专用工作流、专用测试及必要的测试辅助脚本，更新 README 和本规格/实施记录。若实现需要改动生产点云转换、发布、服务或权限逻辑，须先报告原因并重新确认范围。

本轮不做语义分割准确率、Mesh/CAD 质量评价，不给 PR 的不受信任代码开放真实样本，不引入自托管运行器，不开放远程点云服务，不把 1.15 GB 原始 `machine zoom.las` 纳入该门禁。

## 私有样本与凭据

- 建议私有仓库名 `PointCloud-Platform-Private-Fixtures`。仓库 Git 历史只放简短说明，**不追踪 LAS 文件**；以 Release `real-las-v1` 附件上传原始字节，附件名采用不含机电房细节的 `filtered-points-v1.las`。创建前再次确认目标仓库 `visibility=PRIVATE`；上传后从未授权视角验证不可访问。
- 附件版本冻结后，公开工作流中固定 Release 标签、附件名、218,266,379 字节和 SHA-256。附件即使被替换或下载不完整，也必须在进入转换前硬失败。更换样本须显式更新版本和指纹，不能静默改指向。
- CI 使用仅有该私有仓库 `Contents: read` 权限、带到期日的细粒度访问令牌。令牌由用户在 GitHub 页面创建，存入公开仓库的受控 Actions secret；**不粘贴到聊天、脚本、日志、命令行参数或仓库文件**。初版使用独立环境 `private-real-las` 管理该 secret；具体环境保护规则按账户可用功能配置，不能把审批机制当作唯一防线。令牌轮换或失效时该作业明确失败，不降级为跳过。
- 私有数据只能在受信任分支代码上下载。专用作业触发为 `push` 到 `main` 与从 `main` 执行的 `workflow_dispatch`；不接受 `pull_request`、`pull_request_target`、fork 或任意 PR 分支作为私有样本入口。公开 PR 继续运行现有不依赖私有数据的检查。主分支内容仍需人工审查，因为任何能修改运行代码或工作流的受信任提交都可能接触下载后的样本。
- 私有样本作业使用 GitHub 托管的临时 Windows 运行器。下载目录与转换产物只留在该作业工作盘；不配置缓存，不上传原始 LAS、Potree 输出、截图、trace 或含私有数据的失败工件。日志只记录状态、耗时、点数和校验结果，不打印凭据或文件内容。

## CI 执行顺序

1. 检查触发事件与 `refs/heads/main`；检查私有下载凭据已配置，缺失即失败。把 `GITHUB_TOKEN` 权限限定为公开仓库 `contents: read`，私有仓库只读凭据仅暴露给下载步骤。
2. 下载并核对官方 PotreeConverter 2.1.1 Windows x64 包与 Potree 1.8.2 查看器包。下载包 SHA-256 采用 `docs/2026-10-26-potree-compatibility-probe.md` 已记录的固定值；解压后仍通过平台现有执行文件/脚本指纹检查。任何不符均失败，不改用不受控版本。
3. 从私有 Release 获取单个固定 LAS 附件，核对文件大小与 SHA-256；将其保存在工作盘，绝不复制到 Git 跟踪目录。仓库元数据和预期指纹可公开，原始字节不可公开。
4. 安装当前提交所需的 Python/Playwright 依赖。使用当前仓库源码调用 `prepare-full-preview`，以新资产 ID 完整转换 **全部 8,394,852 点**，不得抽样、裁切或只读取文件头。转换门禁验证输入前后指纹、点数、RGB、边界和 Potree 层级。
5. 运行新增的专用 Chromium 浏览器测试：启动只绑定 `127.0.0.1` 的平台预览服务，读取动态活动版本，断言页面就绪、源点数 8,394,852、RGB 状态、可见点数大于零、`hierarchy.bin` 与 `octree.bin` 返回 HTTP 206，并断言浏览器未请求原始 `.las`。测试不依赖既有本机固定 run ID；私有资源缺失时 **fail，不 skip**。
6. 记录测试结论和必要的非敏感诊断；作业结束后由临时运行器销毁工作盘。不得使用现有浏览器失败工件上传路径保存该专用作业的截图或 trace。

## 验收与反证

- 聚焦本地测试覆盖：正确样本通过；缺失令牌/附件、错误 SHA、错误大小、转换器指纹不符、浏览器点数不符或 Range 不为 206 均失败。静态检查确认专用作业仅在可信事件运行，且不上传私有工件。
- 公开 PR 的既有后端/浏览器检查继续执行；新增真实样本作业不会因私有资源缺失在 PR 上伪装成通过。`main` 推送或从 `main` 手动触发时，专用作业必须真实下载并运行，不能出现 `skip`。
- 远端首次运行完成后，核对实际 Actions 日志的成功状态、8,394,852 点、RGB 和浏览器 Range 断言；同时核查日志及公开 Artifacts 未包含 LAS、Potree 产物、截图或 trace。仅本地转换成功不构成 CI 验收。
- 在私有仓库创建、令牌配置、数据上传和远端 CI 任一步无法完成时，清楚标注“未完成”及所需用户动作，不以本地结果替代。

## 已知边界与待确认

- LAS 头部没有单位 VLR；现有预览代码按声明的 `m` 处理。该文件的坐标跨度与此前机电房样本一致，但仍需用户确认导出后单位未改变。
- 私有 Release 附件依赖有期限的只读凭据，需到期前轮换。CI 不运行任何 fork PR 的真实样本测试，因此真实样本不是合并前 PR 门禁，而是 `main` 的后置验收；需要把这一点清楚写入 README。
- 私有仓库创建、Release 上传以及 GitHub secret 配置是外部状态变化；实施时先做权限/目标核对，再执行。若账户权限或网络状态阻止某步，应停在可恢复状态并给出手动操作指引。

## 实施者可自行决定

专用工作流和测试文件的具体名称、临时目录路径、测试辅助脚本拆分方式及非敏感状态输出格式，由实施者按现有项目惯例确定；不改变上述安全边界和验收门禁。
