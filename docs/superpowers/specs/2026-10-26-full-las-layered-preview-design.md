# 完整 LAS 分层预览设计规格

## 意图与现状

用户要在点云平台查看 `machine zoom.las` 的完整机电房扫描，而不是只看四份候选。该文件为 LAS 1.2、RGB 点格式 2，大小 1,245,393,779 字节，头部记录 47,899,752 点。当前浏览器直读页一次性读取、解码和上传所有点，具有 128 MiB / 750,000 点双重上限；简单删除常量会产生数 GiB 级内存峰值和浏览器失效风险。

仓库已经有 `publish-potree` 转换器调用边界，但它只检查 `metadata.json`，没有安装实际转换器、可加载的完整 Potree 页面或支持大二进制分段请求的服务。现有展示页对 Potree 主要提供清单入口，不能据此宣布完整扫描已经在线可视化。

现有 `run_ingest` 经过 `laspy.read()` 会一次性读取整份文件，且资产标识从源文件名推导；`machine zoom.las` 既不适合整文件读入，也包含不符合现有标识规则的空格。本路径应显式给出 `machine-zoom` 等有效资产标识并只读取头部及流式计算指纹，不调用现有整文件 `run_ingest`。

用户提供的 [3d-product-viewer POC](https://github.com/BoChunZengCN/3d-product-viewer) 是 Three.js/Vite 的网格模型预览系统，具有交互视角、进度反馈、服务端转换与静态服务的可参考结构；其现有格式和转换链并不包含 LAS→分层点云，不能直接移植为本次点云加载器。参考其用户交互和任务状态呈现，不复制其认证、数据库或模型转换服务。

## 方案比较与已选方案

- **A：离线转换为 Potree 分层数据，再由平台按需加载。已选。**原始 LAS 保持不变，浏览器不一次性读入 1.25 GB。需要转换器、与格式匹配的查看器资源及支持 HTTP Range 的本地服务。
- B：浏览器分块扫描原始 LAS 并维持固定数量的显示点。准备快，但整体可见点是有损展示，不适合当前细节质量检查。
- C：仅移除 128 MiB / 750,000 点限制。现有数组与显存路径有高失效风险，不采用。

## 目标、边界和明确不做

1. 操作者可针对上述完整 LAS 准备分层预览，并在平台展示页打开；逐级放大查看细节，展示点预算可调，界面明确显示“当前显示点”与“源文件总点数”不同。
2. 保留现有小文件直读页及其安全上限。大文件使用新的完整场景路径，**不是**让旧解析器无限读取。原始 LAS 不复制到仓库、不上传、不改写；转换产物放在忽略的 `workspace/previews/<asset_id>/` 下。
3. 第一版仅供本机操作者使用：明确指定文件路径进行一次准备，服务只绑定 `127.0.0.1`，平台页面通过本地 HTTP 打开。不实现远程共享、多用户权限、浏览器上传 1.25 GB、点云分割、网格生成或 CAD 转换。
4. 任何转换失败、输出缺失、点数不符、源文件变化或页面加载失败，都不得显示“已发布”或“全部点已验证”。

## 后续多格式导入的兼容边界

本轮实现 LAS 完整场景路径，但不能把“平台资产”定义为只能是 LAS 或 Potree。用户已有的 3d-product-viewer POC 列出 STL、OBJ、STEP、IGES、GLTF/GLB、FBX、DXF、XYZ、IFC 等输入；当前点云平台另有 LAS/LAZ 管线以及仅支持 STL/OBJ/PLY 的模型导入。后续应分点云、网格、CAD/BIM 三类设计导入适配器，并归一到平台资产契约：原始文件指纹、来源格式、单位/坐标系、版本与审计、可用派生表示及查看器类型。原始文件须可追溯，派生表示可重建和独立版本化；不强迫所有几何变成同一种二进制，也不把 Potree 格式称作通用平台格式。

本轮只让新分层预览清单显式记录 `source_format=las`、`representation_kind=point_cloud`、`viewer_format=potree2` 及源指纹/单位，保留以后接其他导入器的字段边界；**不**顺带实现 POC 中各格式导入或统一格式迁移。后续多格式导入需另写规格、逐格式验收。

## 用户工作流与实现约定

1. 操作者在本机运行一次“准备完整场景”命令，明确传入原始 LAS 路径、资产标识和经过核验的 PotreeConverter 可执行文件。命令先读取 LAS 头部、记录源大小及 SHA-256，不读取到单个大数组。
2. 调用固定版本的 PotreeConverter 2.x，输出到新的运行目录。先用小型 LAS 做真实兼容性探针，确认转换器、查看器资源和本地服务三者能协同，再处理 1.25 GB 文件。第三方程序及静态资源记录版本、来源和校验值；不静默下载或执行未知二进制。
3. 同一资产同一时刻只允许一个准备/发布运行；并发请求明确拒绝，不依赖“最后写入者获胜”。检查 `metadata.json`、`hierarchy.bin`、`octree.bin` 存在且格式可读；按固定转换器/查看器版本核对元数据 schema、源点数、RGB 属性、边界、层级块大小及二进制偏移不越界，并再次确认源大小及 SHA-256 未变。点数相符仅证明计数一致，不等于逐点内容正确。任一检查失败，运行标记失败且不发布入口。成功后用不可变运行目录和原子更新的活动指针发布，旧成功版本保留供回退，不覆盖旧产物。
4. 平台展示页新增“完整 LAS 分层预览”入口。打开页面时只解析一次活动指针，随后的 `metadata.json`、`hierarchy.bin`、`octree.bin` 均使用相邻的不可变 `run-id` URL；发布或回滚期间，已打开页面不能混读版本。查看器显示源总点数、当前已加载/显示点、颜色状态、加载/失败状态；支持旋转、缩放、平移、标准视角和点预算调节。自动适应场景尺度，坐标单位按用户已确认的 m 标注。浏览器加载按需节点，不承诺 4,789 万点同时在显卡中。
5. 本地只读 HTTP 服务仅提供平台静态资源和已发布预览的白名单文件；`octree.bin`/`hierarchy.bin` 对单段 `bytes=start-end` 必须正确返回 `206`、精确 `Content-Range`/`Content-Length`，无效范围返回 `416`，无 Range 请求不得意外以 `200` 传输整份大文件。元数据及两个二进制文件保持同源、相邻 URL。浏览器不得传入任意磁盘路径来读取服务器文件；原始 LAS 永远不作为 HTTP 静态资源。

## 安全、恢复及追溯边界

- 源路径只来自操作者显式 CLI 参数；进行常规文件与 LAS 头校验。不得由网页查询参数或未经认证的接口触发任意文件读取、转换或删除。
- 静态服务不接受通用文件路径，只将固定端点映射到已批准的静态资源和当前已发布产物；拒绝 `..`、目录枚举及启动时指向边界外的符号链接/Windows 重解析点。绑定回环地址并校验 Host，不配置跨域开放读取。威胁模型不声称能抵御同一账户的恶意本地进程在服务运行期间替换文件系统对象；不得为此叠加未获证实的路径检查与删除补丁。
- 转换器可执行文件必须是明确指定、经版本与校验值记录的外部程序；不使用 shell 字符串拼接。转换有超时/退出码/磁盘空间保护，日志包含运行标识、源指纹、转换器版本、状态、失败原因及发布版本，不包含点记录内容。
- 失败运行保留诊断状态，不递归清理用户目录。启动时只读取完整发布指针；未完成临时目录绝不成为可见版本。回滚仅切换到既有成功版本，不改动原始 LAS。

## 最终复审修订边界（2026-10-26）

本轮只修复最终复审确认的四项重要缺口：发布指针写入失败时的版本可见性、固定 Potree 2.0 元数据与层级门禁、转换器/查看器版本指纹绑定、以及本机展示页误显示演示资产。新增回归测试先红后绿；不扩展 LAZ、多格式、远程服务或语义建模。Range 超长数字属于轻微问题，另记后续事项。

发布顺序的威胁边界保持为单机同账户、正常文件系统原子替换与可捕获异常，不声称跨多个文件实现数据库级事务，也不声称防御同账户恶意进程并发替换文件。失败运行须写入持久失败标记，所有版本读取、回滚与 HTTP 白名单共同拒绝该标记；若失败标记本身无法持久化，应返回明确的人工恢复阻塞，而不能宣称发布成功。固定依赖采用官方发布的精确执行文件/查看器脚本 SHA-256；升级版本须更新兼容探针与常量，不能仅凭路径或文件名接受。

## 验收证据

- 聚焦测试：LAS 头与源指纹、转换器不存在/失败、输出缺失或点数不符、二次源校验、未完成运行不发布、活动版本切换/回滚且旧会话 URL 不混版本、静态路径隔离、HTTP Range 206/416 与无 Range 大文件拒绝。
- 真实探针：先用一份小候选验证浏览器确实出现点和颜色、放大/旋转可用；再用完整 `machine zoom.las` 生成分层数据，比对源点数 47,899,752 与转换结果及源 SHA-256。
- 浏览器验收：平台页面可打开完整场景，能看到真实点和 RGB；真实加载器的 `bytes=start-end` 请求获得局部范围，而非整份 LAS；等待、失败、已加载及显示预算状态准确。四份候选的局部质量判断与完整场景总览分开记录。
- 阶段门禁：聚焦测试、相关集成、静态检查、差异检查和一次全仓测试。旧 Phase 15D 失败已在未修改 `main` 复现，应独立列为已有问题，不能伪称全仓通过。

## 实施边界及留给实施者的决策

允许新增完整场景准备命令、转换与发布验证模块、只读范围服务、平台预览页及其测试/中文说明；允许对现有 Potree 发布适配器和展示入口做最小兼容修改。不更改旧小文件解析器的上限。实施计划中先固定并探测 PotreeConverter 与查看器资源的兼容版本，再决定精确依赖文件和服务接口。若官方二进制或查看器在本机不可获得、无法安全执行或真实样本点数不守恒，停止处理大文件并向用户报告，不用虚假成功状态替代。

当前小文件预览分支已有尚未提交的代码与测试。实施 A 前先完成该批次的精确提交或隔离，避免把两个里程碑混入同一提交；GitHub 推送/合并仍按用户后续验收安排。
