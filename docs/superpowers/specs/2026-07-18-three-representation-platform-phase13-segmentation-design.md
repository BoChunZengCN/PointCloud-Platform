# 三种表达平台与 Phase 13 分割质量基础设计

日期：2026-07-18

状态：已批准（2026-07-19）

首个实施阶段：Phase 13

## 1. 决策摘要

平台采用“一个空间资产，三种互补表达”的架构：

1. 点云是几何真值层，负责测量、计算、分析、变化检测，以及分割和配准的原始依据。
2. 高斯泼溅是视觉体验层，负责照片级真实感、流畅漫游和远程现场理解。
3. 匹配后的三维模型是语义对象层，负责设备个体化、仿真、碰撞分析、台账和运维。

三种表达共享同一套资产标识、坐标参考、空间变换、版本关系、权限和审计记录。它们不是三个相互独立的数据孤岛。

完整愿景包含分割、配准、高斯渲染、对象管理和仿真等多个独立子系统。根据当前优先级，Phase 13 只实现“分割质量基础”。它必须为后续模型检索与配准保留稳定接口，但不在本阶段实现这些后续能力。

## 2. 当前基线

仓库当前完成到 Phase 11。与本设计直接相关的能力包括：

- Phase 6/7：点云采样和统计分析。
- Phase 8/9/11：资产级和项目级质量门禁、交付门禁及报告中心。
- Phase 10：距离连通聚类、物体候选报告、Open3D 注入边界、CLI、API 和前端摘要。
- Phase 2：Gaussian Splatting 外部训练器编排边界。

Phase 10 的优点是轻量、可测试、输出结构稳定，但它还不代表生产级分割：

- 内置聚类是近似的全点对距离搜索，不适合大规模工业点云。
- 固定距离阈值不能适应扫描距离和点密度变化。
- 当前质量结论主要依据噪声率和对象数量，不能衡量粘连、破碎和边界准确性。
- 当前 Open3D 路径在没有真实执行器时使用内置算法回退，但仍标记为 `open3d_dbscan`；这会形成错误审计信息。
- 输出未完整记录数据版本、算法版本、配置指纹和处理血缘。

## 3. Phase 13 目标与非目标

### 3.1 目标

Phase 13 建立可复现、可比较、可扩展的分割质量基础：

- 原始点云保持不可变，所有处理产生派生资产和血缘记录。
- 预处理、分割、评估通过稳定接口解耦。
- 先支持可解释的几何算法，并允许以后接入 Open3D、PCL 或学习模型。
- 同时支持“无人工标注的运行质量评估”和“有黄金标注的准确率评估”。
- 每次运行都可复现、可比较、可审计，并可被后续模型匹配直接消费。
- 针对工业生产线、化工管线、机房和海上平台场景，避免因过度清洗删除细管、边缘和局部构件。

### 3.2 非目标

Phase 13 不包括：

- 训练语义或实例分割神经网络。
- CAD/三维模型检索和点云配准。
- 自动生成或发布新的 CAD 模板。
- 高斯泼溅渲染器替换或三种表达的同步查看器。
- 碰撞、搬运、安装和改造仿真。
- 完整的人工逐点标注界面。
- 生产数据触发后直接修改线上模型的在线学习。

这些能力分别进入后续独立阶段，避免 Phase 13 变成不可验证的大型集成。

## 4. 平台长期架构

### 4.1 统一空间资产

统一空间资产是三种表达的连接点，至少包含：

- `asset_id`：稳定资产标识。
- `asset_version`：源数据版本。
- `coordinate_reference`：坐标系、单位和轴约定。
- `transform_to_project`：到项目坐标系的刚体或相似变换。
- `representation_type`：`point_cloud`、`gaussian_splat` 或 `semantic_model`。
- `derived_from`：派生来源和处理运行。
- `created_at`、`created_by`：时间和责任主体。
- `quality_status`：`passed`、`review_required` 或 `blocked`。

点云、高斯泼溅和三维模型可以有不同文件格式与存储策略，但必须通过上述关系映射到同一个项目空间。

### 4.2 职责边界

点云层承担几何真值职责。高斯泼溅不作为精密尺寸和碰撞计算的唯一依据。匹配模型承担语义、参数和业务操作职责，但其位置及尺寸必须能回查点云配准残差。

后续任何应用应显式选择所需表达：

- 测量和变化检测读取点云。
- 漫游和远程展示优先读取高斯泼溅。
- 仿真、设备台账和运维读取语义模型。
- 需要可信结论时，应用同时显示来源版本和质量状态。

## 5. Phase 13 组件设计

### 5.1 分割运行模型

新增独立的 `SegmentationRun` 概念，避免用单个最新报告覆盖历史结果。每次运行记录：

- `run_id`
- `asset_id` 和 `asset_version`
- `source_uri`
- `source_point_count`
- `coordinate_reference`
- `preprocessing_steps`
- `requested_engine`
- `executed_engine`
- `algorithm_version`
- `config` 和 `config_fingerprint`
- `started_at`、`completed_at` 和 `status`
- `artifacts`
- `quality`
- `error`

运行结果写入：

```text
reports/segmentation_runs/<asset_id>/<run_id>/
  segmentation_run.json
  object_segments.json
  segmentation_quality.json
  segmentation_quality.md
  artifacts/
```

为保持兼容，现有：

```text
reports/object_segments/<asset_id>/object_segments.json
```

继续作为“最新成功运行”的兼容投影，而不是唯一事实来源。

### 5.2 预处理管线

预处理步骤必须可组合且默认保守：

1. 输入验证：拒绝缺少 XYZ、非有限数值、无法确认单位或坐标约定的数据。
2. 重复点处理：记录删除数量，不改变原始文件。
3. 可选体素采样：用于算法计算副本，保留采样前后点数和体素尺寸。
4. 可选离群点过滤：支持统计式或半径式策略，输出保留率。
5. 可选结构分离：平面、地面或用户指定区域只作为带标签的派生结果，不永久删除源点。

所有阈值使用点云单位，并在配置中显式记录。细管、线缆、扶手和薄壁属于高风险结构；当清洗导致局部结构点数显著下降时，运行必须进入 `review_required`，不能自动判定为更高质量。

### 5.3 分割引擎接口

分割引擎接收标准化点记录或点云工件，并返回统一候选对象结构。Phase 13 支持：

- `builtin_geometric`：保留当前轻量基线，用于小样本和回归测试。
- `open3d_dbscan`：真实 Open3D 执行器存在时才允许使用此标识。
- `external`：为 PCL、PDAL 或后续学习模型保留进程外适配器。

系统必须分别记录 `requested_engine` 和 `executed_engine`。真实引擎不可用时：

- 默认失败并给出可操作错误。
- 只有配置显式允许回退时才能运行基线。
- 回退结果必须标记实际执行的 `builtin_geometric` 和 `fallback_reason`。

引擎内部实现可以替换，但不得改变公共运行和对象契约。

### 5.4 对象候选契约

`object_segments.json` 升级为向后兼容的新版本。每个对象候选至少包含：

- `object_id`
- `label`
- `confidence`
- `point_count`
- `bounds`
- `center`
- `method`
- `point_membership_artifact`
- `density_summary`
- `quality_flags`

对象点成员关系写入独立工件，避免在摘要 JSON 中嵌入大型点索引数组。后续模型检索通过 `point_membership_artifact` 取得单对象点云，而不是再次猜测对象边界。

对象标识只在一个分割运行内稳定。跨运行或跨时间的对象身份关联属于后续“对象管理”阶段，不在 Phase 13 假定 `obj-001` 永久代表同一设备。

### 5.5 两套质量评估

#### 无黄金标注：运行质量

生产点云通常没有真值标签，因此系统使用代理指标发现明显风险：

- 有效点保留率。
- 噪声点比例。
- 极小碎片比例。
- 最大对象占比和疑似粘连。
- 对象密度分布。
- 包围盒异常。
- 多组相邻参数运行的一致性。
- 预处理前后薄结构保留警告。

这些指标只能判断“是否值得复核”，不能宣称真实分割准确率。

#### 有黄金标注：准确率

基准数据包含点级或实例级真值时，计算：

- 点级 IoU 和 mIoU。
- 实例 precision、recall 和 F1。
- 过分割数量。
- 欠分割/粘连数量。
- 边界质量。
- 各场景、各对象类型和各点密度区间的分项结果。

只有黄金数据评估结果可以用于声明算法准确率提升。

### 5.6 基准数据清单

新增版本化 benchmark manifest，划分：

- `development`：参数开发数据。
- `validation`：阶段验收数据。
- `golden_regression`：不可随意修改的历史回归集。

每个样本记录扫描设备、场景类型、点密度、坐标单位、遮挡程度、标签版本和授权信息。黄金回归集至少覆盖：

- 密集交织管线。
- 大型设备与相邻小构件。
- 地面、墙面和设备相连场景。
- 低密度、遮挡及反光导致缺失的点云。
- 细管、线缆、扶手和薄壁。
- 相似设备并排或接触的场景。

训练或调参过程不得使用 `golden_regression` 的标签作为输入。

### 5.7 CLI、API 与报告

Phase 13 计划提供下列公共入口：

```text
plan-segmentation
run-segmentation
evaluate-segmentation
compare-segmentation-runs
```

API 提供：

```text
GET /segmentation-runs/<asset_id>
GET /segmentation-runs/<asset_id>/<run_id>
GET /segmentation-runs/<asset_id>/<run_id>/quality
```

Phase 13 前端只展示运行列表、实际算法、质量状态和核心风险，不建设完整标注编辑器。人工纠正界面进入下一阶段。

## 6. 数据流

```text
不可变原始点云
  → 输入质量验证
  → 保守预处理派生数据
  → 分割引擎
  → 对象候选与成员工件
  → 无标注运行质量评估
  → 可选黄金标注准确率评估
  → passed / review_required / blocked
  → 最新兼容报告
  → 后续模型检索与配准
```

每一步产生机器可读 JSON 和必要的人工可读报告，并记录输入、配置、版本和输出路径。

## 7. 状态与错误处理

- `blocked`：输入数据无效、坐标或单位不明确、引擎执行失败、输出契约无效。
- `review_required`：噪声过高、疑似粘连或过分割、薄结构损失、稳定性不足、显式回退。
- `passed`：所有配置的运行质量门禁通过；如果存在黄金标签，准确率门禁也必须通过。

运行失败不得覆盖最后一次成功结果。错误记录必须包含错误代码、阶段、可读信息和是否可重试。外部引擎的标准输出和错误输出只保存到运行日志，不直接暴露敏感文件路径给未经授权的前端用户。

## 8. 测试与验收

### 8.1 测试层级

- 单元测试：配置校验、预处理统计、对象契约、质量指标和状态映射。
- 合成几何测试：分离对象、接触对象、细管、平面背景、离群点和密度变化。
- CLI/API 集成测试：运行创建、工件写出、历史列表、错误状态和兼容投影。
- 引擎契约测试：注入假执行器；真实 Open3D 测试作为可选测试，不成为轻量核心测试的硬依赖。
- 回归测试：现有 Phase 1-11 测试必须继续通过。
- 性能基线：记录点数、耗时和峰值内存；本阶段先建立可比较基线，不承诺超出样本验证范围的生产吞吐。

### 8.2 Phase 13 验收条件

- 相同输入和配置得到确定性的运行结构与配置指纹。
- 原始点云文件从不被就地修改。
- 请求引擎、实际引擎和回退原因审计准确。
- 每个对象候选都能定位到独立点成员工件。
- 无标签报告不再把代理指标描述为准确率。
- 有标签评估能报告粘连、过分割和实例级指标。
- 失败运行不覆盖最新成功兼容报告。
- Phase 1-11 全量回归通过。

## 9. 阶段拆分

Phase 13 内部按下列顺序交付：

1. P13-M1：运行、配置指纹、工件和兼容投影契约。
2. P13-M2：保守预处理管线及血缘统计。
3. P13-M3：分割引擎接口和真实执行/回退审计。
4. P13-M4：无标注运行质量门禁。
5. P13-M5：黄金标注准确率评估和运行比较。
6. P13-M6：CLI、API、轻量前端摘要、文档和全量回归。

后续建议：

- Phase 14：可视化人工纠正、反馈事件和主动学习样本选择。
- Phase 15：三维模型库、候选检索、粗配准、精配准和残差门禁。
- Phase 16：点云、高斯泼溅和语义模型的统一对象查看器。
- Phase 17：Champion/Challenger、离线重训练、漂移检测和受控持续学习。
- 后续独立阶段：仿真、对象全生命周期管理和跨时间资产关联。

## 10. 关键风险与控制

- 过度去噪：保留原始数据、记录保留率、对薄结构设置警告。
- 阈值依赖点密度：支持按场景配置并加入稳定性比较，不假设单一全局阈值。
- 大规模性能：保留轻量基线用于测试，生产引擎通过适配器扩展。
- 假准确率：区分无标签代理质量与有标签真实准确率。
- 错误自学习：Phase 13 不进行在线更新，人工反馈进入版本化数据集后才可训练。
- 三种表达漂移：统一记录坐标、变换、来源版本和质量状态。

## 11. 已确认假设

本规格根据用户“开始执行开发工作”的指令，采用此前推荐方案 B：

> 一个空间资产，三种表达；点云为几何真值，高斯泼溅负责视觉体验，匹配模型负责语义、仿真和管理。

当前首要开发目标是提高分割质量，并为后续检索和配准提供更可靠的单对象点云。Phase 13 不以“完全无噪声”为目标，而以“保留有效几何、识别风险并可量化比较”为目标。
