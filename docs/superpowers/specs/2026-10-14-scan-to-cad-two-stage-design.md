# 点云到CAD两层逆向建模设计规格（Scan-to-CAD）

**日期：** 2026-10-14

**状态：** 五个设计部分已经用户确认；本文完成后仍需用户审核书面规格，审核通过后才能编写实施计划和生产代码。

**代码基线：** origin/main，054c9bf（Phase 15E 工程范围已合并）。

## 1. 已确认的决策

- 采用“两层实施”：第一层为点云到可验证三角网格，第二层为原始点云与网格双证据到可编辑 CAD。
- 第一版主要 CAD 输出为 STEP/B-Rep。
- 第一版只处理经过 Phase 14 人工确认或 Phase 15E 专家核验的单对象点云，不直接处理整厂或整场景。
- 第一版优先支持管道、法兰、罐体、梁柱；复杂自由曲面、泵壳和任意机械零件后置。
- 采用 Open3D + OpenCascade 的开源方案；二者作为可替换外部工作器，不嵌入 API 进程。
- 网格和 CAD 都使用 passed、review_required、rejected 三态门禁。
- rejected 不能进入下游；review_required 必须由专家明确放行。
- CAD 自动结果只是候选，经过质量检查和专家批准后才成为不可变发布版本。
- 所有自动运行、人工修改、批准、驳回、替换、回滚和恢复必须可审计。
- 第二层同时读取原始审查点云和已批准网格；不能只依赖可能经过平滑的网格确定尺寸。

任何实质改变输入信任边界、几何语义、持久化不变量、审批规则或用户工作流的实现，都必须停止并重新确认。

## 2. 目标与成功标准

### 2.1 交付目标

平台新增一条受控快速建模链路：

已审查单对象点云 → 网格重建 → 网格质量门禁 → passed自动放行或review_required专家放行 → 参数化几何拟合 → B-Rep/STEP 生成 → 双证据质量门禁 → 专家批准 → CAD 版本发布。

成功不是“生成一个看起来像模型的文件”，而是同时满足：

- 来源点云、网格和 CAD 均有不可变版本及指纹。
- STEP 可以由 OpenCascade 重新读取并通过拓扑检查。
- CAD 的尺寸、位置和方向可以追溯到原始点云证据。
- 点云—网格、点云—CAD、网格—CAD指标完整可读。
- 自动参数与人工修订参数分别保存。
- 失败不会改变当前已发布 CAD 头。
- 旧 CAD 模型库、扫描参考模板、检索、配准和绑定继续兼容。

### 2.2 面向用户

- 专家用户：创建运行、查看证据、修订参数、批准、驳回、重新运行和回滚。
- 普通业务用户：只查看当前已发布 CAD、来源、状态和业务摘要。
- 审计用户：读取运行、人工决定、发布和恢复的完整审计证据。

## 3. 本阶段范围

### 3.1 第一层包含

- 从 Phase 14 纠正发布或 Phase 15E 已核验版本解析单对象点云。
- 冻结来源、单位、坐标、点记录、版本和 SHA-256。
- 版本化网格重建配置。
- Open3D 法向量估计、方向统一和表面重建。
- Poisson 与 Ball Pivoting 两种显式算法配置；不得静默切换算法。
- 退化面、重复顶点、小型孤立组件和非有限数据检查。
- 保守网格修复，不允许无证据的大范围补形。
- 原始网格、修复网格、预览网格、运行报告和质量报告。
- 网格候选三态门禁、专家审批和不可变网格发布。

### 3.2 第二层包含

- 同时读取原始审查点云和已批准网格。
- 版本化对象族、拟合配置、目录配置和质量策略。
- 管道、法兰、罐体、梁柱的参数候选。
- OpenCascade B-Rep 构造、拓扑检查、STEP 导出和重读。
- CAD 预览网格和参数摘要。
- 点云—CAD、网格—CAD双向质量评估。
- CAD候选三态门禁、专家修订、批准、发布、替换和回滚。
- CAD发布后进入现有模型库审核流程的显式入口。

### 3.3 明确不做

- 不对整厂点云自动分割并批量生成 CAD。
- 不把未审查的原始扫描直接送入重建。
- 不实现任意自由曲面、复杂泵壳、叶轮、铸件或人体等通用逆向工程。
- 不承诺从严重遮挡或缺失数据恢复真实不可见结构。
- 不自动识别并建模法兰螺栓孔、罐体喷嘴、扶梯、支座或内部结构。
- 不实现装配约束求解、工艺设计、强度计算或制造认证。
- 不在首版输出原生 SolidWorks、Inventor、Plant 3D 或 Revit 文件。
- 不实现整厂拓扑、P&ID自动关联、BOM/MTO或设备生命周期。
- 不实现 Phase 16 的点云、高斯泼溅和模型统一漫游查看器。
- 不实现自动训练、在线学习、参数自动推广或无人审批发布。
- 不自动把新发布 CAD 加入生产检索索引。
- 不允许 API 提交任意本机路径、URL、压缩包或 Shell 命令。
- 不自动递归删除、移动或隔离失败工作目录。

## 4. 架构

### 4.1 核心与工作器分离

平台核心继续负责可信身份、请求规范化、版本、状态机、审计、门禁、审批和发布。

重型几何计算由两个外部工作器完成：

- Open3D 网格工作器：点云到网格及网格统计。
- OpenCascade CAD工作器：参数到B-Rep、STEP及拓扑统计。

工作器必须通过版本化 JSON 请求和结果清单通信。核心不得导入工作器内部对象，也不得根据工作器目录结构猜测结果。

商业逆向工程工具可以在后续实现为相同契约的替代工作器，不改变核心状态机。

### 4.2 组件

1. 输入冻结器
   - 读取并验证受支持的来源。
   - 生成局部米制点云快照和来源指纹。

2. 网格运行服务
   - 创建网格运行、参数版本和工作目录。
   - 调度工作器并验证返回工件。

3. 网格质量服务
   - 计算拓扑、距离、覆盖率和修复偏移。
   - 生成三态门禁。

4. 网格审批与发布服务
   - 记录专家决定。
   - 发布不可变网格版本和当前头。

5. CAD拟合服务
   - 按对象族生成确定性参数候选。
   - 同时使用点云和网格证据。

6. CAD构造工作器
   - 使用OpenCascade构造B-Rep。
   - 输出BREP、STEP、预览网格和拓扑报告。

7. CAD质量服务
   - 计算双向残差、覆盖率、尺寸和对象族指标。
   - 验证STEP重读结果。

8. CAD审批与发布服务
   - 冻结自动参数和人工修订参数。
   - 发布、替换和回滚不可变CAD版本。

9. Scan-to-CAD工作台
   - 提供任务列表、证据、修订、审批和历史。

## 5. 输入契约

### 5.1 允许来源

第一版允许：

- Phase 14 已发布纠正版本中的单个 instance_id。
- Phase 15E 已通过专家核验的扫描参考版本。

Phase 13A实验运行、未发布纠正草稿、未核验扫描版本和任意文件路径不得作为生产输入。

### 5.2 来源快照

每次运行冻结：

- source_kind；
- asset_id、source_id、instance_id或model_id、version_id；
- 来源发布指纹；
- 原始点记录工件指纹；
- 单位和坐标处理版本；
- 局部坐标原点；
- 点数、包围盒和有限数值统计；
- 发起主体、请求、时间和审计操作。

来源变化不会修改已存在的运行。新来源必须创建新运行。

### 5.3 对象族

对象族必须为 pipe、flange、tank、beam_column 之一。

平台可以依据现有类别映射给出建议，但专家在CAD运行开始前必须确认。首版不自动改变对象族。

### 5.4 坐标和单位

- 内部坐标统一为米。
- 保留来源到局部坐标、局部坐标到CAD坐标的4x4刚性变换。
- 不允许隐式缩放、反射、错切或单位猜测。
- STEP使用米制几何语义，导出器必须明确记录文件单位。
- 大地经纬度坐标不得直接进入几何工作器。

## 6. 第一层：点云到网格

### 6.1 网格配置

网格配置是不可变工件，至少包含：

- config_id与schema_version；
- algorithm：poisson或ball_pivoting；
- 法向量邻域和方向策略；
- 体素降采样设置；
- Poisson深度、密度裁剪策略；
- Ball Pivoting半径列表；
- 小组件处理阈值；
- 简化目标；
- 资源上限；
- 工作者镜像或二进制版本。

API请求只能引用已发布配置，不能直接上传任意算法参数。

### 6.2 算法语义

- poisson适合近似连续表面，可能补出未扫描区域，因此必须报告密度裁剪和新增封闭表面风险。
- ball_pivoting更保守地连接已有点，但对点密度和法向量敏感。
- 算法由配置显式选择；工作器不得在失败时静默改用另一算法。
- 重建前允许确定性体素降采样，但原始冻结点云保持不变。
- 修复只能删除已证明无效的元素、统一法向和处理有界小组件。
- 填洞、平滑和重网格化若改变尺寸，必须作为显式、版本化操作并报告偏移；首版默认关闭大范围填洞。

### 6.3 网格工件

每次运行至少生成：

- mesh_run.json；
- source_snapshot.json；
- worker_request.json；
- worker_result.json；
- raw_mesh.ply；
- repaired_mesh.ply；
- preview_mesh.glb；
- mesh_quality.json和中文摘要；
- events.jsonl。

所有路径均为相对工件标识，清单记录字节数和SHA-256。

### 6.4 网格状态机

created → queued → running → validating → review_required或passed或rejected。

passed可以由系统按已批准策略发布；review_required必须由专家明确放行后发布；rejected不得进入published。专家仍可对passed结果发起重跑或在CAD运行前阻止使用，但该检查不是正常链路的强制人工步骤。

工作器失败进入failed；已生成但无法证明发布完整性时进入recovery_required。

## 7. 第二层：双证据到CAD

### 7.1 拟合原则

- 尺寸主要从原始点云拟合，网格用于连续表面、边界和形状证据。
- 自动拟合不修改原始点云或已发布网格。
- 每个参数包含数值、单位、估计方法、支持点数量、残差和置信状态。
- 目录吸附必须显式启用，并同时保留测量值、目录值和吸附后的残差变化。
- 人工修订保存为独立revision，不能覆盖自动参数。

### 7.2 管道

首版支持单一连续直管段：

- 中心轴；
- 外径；
- 长度；
- 两端截面；
- 圆柱支持率。

弯头、三通、变径和管线系统拓扑不在首版自动构造范围。它们后续可以在多个已验证直管段之上增加。

### 7.3 法兰

首版支持简化法兰体：

- 主轴；
- 端面；
- 外径；
- 厚度；
- 可验证时的内孔直径。

不自动生成螺栓孔、密封面等级和标准号。目录吸附必须由专家确认。

### 7.4 罐体

首版支持单一圆柱筒体及可见平端：

- 主轴；
- 筒体半径；
- 筒体长度；
- 可见端面。

椭圆封头、球冠、喷嘴、支座和内部结构后置。

### 7.5 梁柱

首版支持：

- 实心矩形截面；
- 矩形中空截面；
- I/H型截面。

输出中心线、长度、方向、截面尺寸和目录匹配证据。节点板、螺栓、焊缝和连接件后置。

### 7.6 CAD工件

每次CAD运行至少生成：

- cad_run.json；
- source_snapshot.json；
- mesh_snapshot.json；
- auto_parameters.json；
- parameter_revisions.jsonl；
- worker_request.json；
- worker_result.json；
- model.brep；
- model.step；
- preview_mesh.glb；
- topology_report.json；
- cad_quality.json和中文摘要；
- events.jsonl。

### 7.7 CAD状态机

created → queued → fitting → building → validating → review_required或passed或rejected。

passed和review_required都必须由专家提交approve才能进入approved；review_required还必须确认具体风险码。rejected不能进入approved。approved再由独立发布操作生成published版本。

审批和发布分开；批准候选不自动改变当前CAD头。

## 8. 质量策略

### 8.1 策略版本

网格质量策略和CAD质量策略分别版本化。生产模式必须引用已批准策略，不能使用隐藏默认值。

仓库可以提供engineering-fixture-v1用于合成夹具，但该策略不得被描述为真实生产精度。

真实生产策略必须记录扫描设备、点间距、预处理方法、业务对象族和审批人。

### 8.2 网格指标

- 非有限顶点和索引；
- 重复顶点；
- 退化三角面；
- 非流形边；
- 边界边；
- 自交；
- 连通组件数量；
- 最大组件占比；
- 法向一致性；
- 点云到网格P50、P95和最大距离；
- 网格到点云覆盖率；
- 修复前后表面位移；
- 三角面和工件资源上限。

是否要求水密必须按对象族和扫描覆盖显式配置。首版不能因为真实扫描存在遮挡就虚构封闭表面。

### 8.3 CAD通用指标

- OpenCascade拓扑有效性；
- B-Rep实体数量和类型；
- STEP导出—重读成功；
- 重读后包围盒、体积和拓扑摘要一致性；
- 点云到CAD表面的P50、P95和最大距离；
- CAD表面到点云覆盖率；
- 网格与CAD双向距离；
- 尺寸、方向和单位一致性；
- 自动参数与人工修订差异。

### 8.4 对象族指标

- 管道：轴线误差、直径误差、长度、圆柱支持率。
- 法兰：轴线同轴度、端面位置、外径、厚度和内孔证据。
- 罐体：主轴、半径、筒体长度和端面证据。
- 梁柱：中心线、截面尺寸、长度、方向和目录差异。

### 8.5 三态门禁

- passed：所有硬约束通过，风险低，可以进入审批或下一阶段。
- review_required：几何可用但存在明确风险，只能由专家放行。
- rejected：输入、拓扑、资源、残差或证据不满足硬约束，不能人工强制发布。

专家可以调整参数并创建新revision或新运行，不能把rejected原地改成passed。

## 9. 人工审批与版本

### 9.1 网格审批

专家查看点云、原始网格、修复网格和质量证据后，可以：

- approve；
- reject；
- request_rerun。

passed网格不强制人工审批，可以由系统按已批准策略发布；review_required必须由专家approve。专家也可以对passed网格主动提交reject或request_rerun。审批冻结候选指纹、质量策略和当前头；候选变化或头变化时旧请求冲突失败。

### 9.2 CAD审批

专家查看双证据、参数、预览和质量报告后，可以：

- 保存参数revision；
- 重新构建候选；
- approve；
- reject；
- request_rerun。

业务用户不能修改几何参数或批准CAD。

### 9.3 发布和回滚

- CAD发布产生不可变cad_version_id。
- current_cad_release是单独的可比较投影。
- 发布、替换和回滚必须带expected_current_version，防止丢失更新。
- 回滚创建新的发布事件，不删除历史版本。
- 发布CAD不会自动加入模型检索索引；必须经模型库导入/关联和既有索引发布流程。

## 10. 安全与威胁边界

### 10.1 信任模型

- 文件名、扩展名、点记录、网格、工作器输出和客户端参数均不可信。
- 可信主体来自生产token映射，不接受请求体自报身份。
- 工作器二进制路径和参数模板由部署管理员配置。
- API不能传入任意服务器路径、网络URL或命令片段。

### 10.2 路径与文件系统

- 只使用受控根目录下的相对工件标识。
- 拒绝路径穿越、绝对路径、符号链接、重解析点、设备文件和非普通文件。
- 发布前重新验证文件身份、字节数和指纹。
- 每个操作使用核心创建的独占目录和所有权标记。
- 不对未知目录做自动递归删除、移动或隔离。
- 失败暂存按配额保留，由独立维护操作在验证所有权后清理。

### 10.3 资源限制

部署配置必须限定：

- 输入字节数；
- 点数；
- 三角面和顶点数；
- 连通组件数；
- 工作器并发；
- CPU时间和墙钟时间；
- 内存；
- 输出文件数量和总字节数；
- STEP重读复杂度。

普通请求只能选择已发布资源策略，不能提高上限。

### 10.4 工作器隔离

- 工作器只读输入快照，只写自己的输出目录。
- API进程不执行用户提供的Shell。
- 工作器退出码、标准错误摘要、版本和运行时长写入审计。
- 工作器崩溃、超时或输出损坏均不得产生可见发布。

## 11. 并发、持久化与恢复

- 网格运行和CAD运行均使用operation_id、request_id和idempotency_key。
- 相同幂等键只允许一个规范请求；不同请求指纹产生冲突。
- 同一来源和配置允许创建不同显式运行，但不得共享可变工作目录。
- 发布使用对象级资源锁和expected-head比较。
- 工件生成、工件验证、审批、发布和审计完成是不同状态。
- 重启恢复只依据冻结请求、所有权、工件指纹和审计事件，不依据目录存在性猜测成功。
- 发布前失败不改变当前头。
- 发布工件可见但审计未完成时进入recovery_required，禁止下游读取为有效版本。
- 恢复只能补齐同一操作的确定性步骤，不能重新执行不同算法或替换参数。
- 任何无法证明所有权或完整性的状态必须失败关闭并等待人工维护。

## 14. 与现有系统的关系

- Phase 14负责分割纠正和审查发布，本模块不重写分割。
- Phase 15E负责扫描参考版本和核验，本模块不修改其不可变版本。
- Phase 15A模型库继续管理正式模型资产。
- Phase 15B索引只接收经过现有发布流程纳入的模型，不直接索引CAD候选。
- Phase 15C配准可以用于发布后模型验证，但不代替Scan-to-CAD质量门禁。
- Phase 15D绑定继续引用明确模型版本，不因新CAD发布自动替换。
- Phase 15F未来可以优化网格和CAD参数，但不得绕过本规格的验证和审批。
- Phase 16未来复用预览工件实现统一查看。
- Phase 17未来可以使用人工revision作为训练反馈，但不能自动推广。

## 16. 测试与验证

### 16.1 几何单元测试

- 带噪、缺失面和离群点的合成管道、法兰、罐体和梁柱；
- 验证轴线、直径、长度、截面和方向；
- 验证算法确定性和显式失败。

### 16.2 工件契约测试

- 来源快照、配置、指纹和状态机；
- 不可变网格与CAD版本；
- 自动参数和人工revision分离；
- 发布、替换和回滚。

### 16.3 工作器集成测试

- Open3D真实生成网格；
- OpenCascade真实构造B-Rep；
- STEP导出—重读；
- 工作器版本和输出清单。

核心测试使用确定性伪工作器，CI默认不强制安装全部重型依赖。真实工作器测试使用独立可选任务并明确跳过原因。

### 16.4 安全与恢复测试

- 路径穿越、绝对路径、链接、非普通文件；
- 超大输入、非有限值、超时、崩溃和损坏输出；
- 幂等冲突、并发审批、预期头冲突；
- 发布前失败、发布后审计失败和重启恢复；
- 未确认所有权时不自动清理。

### 16.5 API、CLI和浏览器测试

- 权限和结构化错误；
- 有界列表分页；
- 运行创建、证据查看、revision、批准、驳回、发布和回滚；
- 普通用户与专家字段隔离；
- 旧Phase 15页面和API回归。

### 16.6 真实业务验收

工程实现通过后，另行收集真实管道、法兰、罐体和梁柱扫描，记录：

- 扫描设备和采集方式；
- 单位、点间距和预处理；
- 人工真值；
- 点云—网格误差；
- 点云—CAD误差；
- 尺寸误差；
- 覆盖率；
- 专家结论；
- 失败和拒绝样本。

合成夹具和确定性伪工作器只证明代码链路，不证明现场准确率或制造精度。

## 17. 分层交付顺序

本规格统一定义两层架构和跨层不变量，但实施不得使用一个超大计划一次完成全部内容。书面规格批准后先为第一里程碑编写并执行独立实施计划；第一层验收完成并冻结真实接口后，再为第二里程碑编写独立实施计划。真实样本验收另列第三份执行清单。

### 17.1 第一里程碑：点云到网格

- 输入冻结和配置；
- Open3D工作器契约；
- 网格运行、质量、审批和发布；
- API、CLI、专家页面的网格部分；
- 安全、恢复和回归测试。

第一里程碑必须独立可用并通过验收，之后才进入第二层。

### 17.2 第二里程碑：网格与点云到CAD

- 对象族拟合；
- OpenCascade工作器；
- B-Rep、STEP和预览；
- 双证据质量门禁；
- 参数revision、审批、发布和回滚；
- 模型库受控入口及完整页面。

### 17.3 第三里程碑：真实样本验收

- 真实样本策略标定；
- 分对象族验收报告；
- 生产配置审批；
- 部署与运维说明。

## 18. 验收标准

满足以下条件才可以声明工程范围完成：

1. 两层均使用经过审查的单对象点云，并冻结完整来源证据。
2. Open3D和OpenCascade通过工作器契约接入，API不执行任意命令。
3. 至少一个管道、法兰、罐体和梁柱合成样本完成端到端流程。
4. 网格和CAD均产生不可变候选、质量报告、审批和发布历史。
5. STEP可以重读，B-Rep拓扑和双证据质量指标通过策略。
6. rejected不能被人工强制发布。
7. 自动参数和人工revision均可追溯。
8. 并发、幂等、中断恢复、路径和资源攻击测试通过。
9. 普通用户、专家和审计员权限及字段投影正确。
10. 现有Phase 14和Phase 15A–E回归通过。
11. 文档、API、CLI和真实浏览器流程一致。
12. 工程完成声明明确排除真实生产精度；真实样本验收必须单独报告。
