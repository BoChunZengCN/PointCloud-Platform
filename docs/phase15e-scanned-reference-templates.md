# Phase 15E：实物扫描参考模板

## 状态与边界

Phase 15E 已完成工程实现验收：扫描参考模板可不依赖 CAD 完成导入、自动质量检查、专家最终核验、模型发布、统一表达和特征索引、Top-K 检索、刚性配准及人工不可变绑定。旧 CAD 工件继续按既有只读契约加载；本阶段不把 CAD 与扫描合并为同一资产的双表达，也不训练、自学习或自动调参。

工程验收已完成，但真实业务样本验收未完成。仓库没有用户提供的独立重复扫描正例和相似不同型号负例；工程夹具只证明代码链路与工件契约，不能代表现场准确率、生产准确率或泛化能力。

## 三步工作流

1. 专家创建 `scanned_reference` 模型资产，将受控暂存区的 LAS、受支持 LAZ 或 PLY 导入为不可变版本。源文件冻结，系统在局部米制坐标下生成质量报告；硬失败不能人工放行。
2. 专家确认单对象、元数据与许可、覆盖限制后形成唯一最终核验，再发布或回滚模型版本。发布和索引发布是两个独立步骤；页面会明确提示“模板已发布，索引需要更新”。
3. 对已确认的场景对象执行生产 Top-K 检索，冻结候选输入并进行刚性配准。操作员只能对通过门禁的候选做人工确认；绑定固定引用候选版本、表达、配准证据和矩阵，后续模板发布不会改变既有绑定。

## 权限、来源与接口

专家可创建扫描资产、导入、核验、发布、构建索引和执行专业配准；操作员可查看裁剪后的状态并确认合格候选；审计员只读。API/CLI 使用可信主体投影，公开/业务响应不暴露扫描来源正文。扫描版本管理接口和 `model-reference-*` CLI 命令提供受控导入、目录、详情与审计读取；管理页面为 `frontend/model-reference-library.html`。

来源类型是显式契约：扫描统一表达为 `scanned_reference`，旧 CAD 采样表达为 `cad_sampled`。服务不通过目录猜测类型；旧 1.0/1.1 索引、候选、配准报告和 1.0 绑定维持只读兼容。

## 版本、索引、恢复与审计

扫描导入、核验、表达、索引、发布、配准和人工决定均保存不可变工件与哈希链审计。版本发布、回滚和索引发布追加历史，不覆盖原记录；恢复仅复用原操作身份。生产索引只收录已核验且已发布的版本，索引配置、表示、特征与候选都冻结来源和指纹。任何恢复不确定状态维持可恢复屏障，而不是由其他请求接管。

工程全链测试生成两个独立扫描模型：同对象的参考与场景来自不同点集生成过程（平移、顺序变化和有界扰动），另一个相似不同型号几何进入同一候选池。它断言正例 Top-1、负例身份、双向覆盖与残差门禁、人工绑定、第二版本追加/回滚和旧不可变工件 SHA-256 不变，并确认未生成 `.obj`、`.stl` 或 `cad_mesh` 占位物。旧 CAD 1.0/1.1 索引、候选、配准和绑定由阶段回归持续验证。

## 验证结论与真实样本缺口

工程夹具验收：完成。它不是现场扫描性能研究，测试中的确定性配准引擎只用于稳定验证工件流转和门禁消费。

本阶段最终非浏览器门禁为 `1335 passed, 1 skipped, 2 warnings`（662.65 秒）；完整 Chrome 浏览器门禁为 `16 passed`（95.58 秒）。跳过项是本机未安装可选 Open3D 时的集成测试，两个警告是既有 Starlette/httpx 和 AnyIO 弃用提示。浏览器首次启动曾在收集前发现本地测试环境未同步 `browser-test` 的 `uvicorn`（0 用例执行）；同步项目已声明的可选依赖后，实际门禁通过。上述统计只证明工程链路和回归范围。

真实业务样本验收：未完成。后续验收至少需要：

- 一组独立重复扫描正例和一组相似但不同型号负例；
- 每个样本的扫描设备、单位、预处理和采集说明；
- 人工真值、Top-K 顺序、双向残差、覆盖率和人工绑定结论；
- 明确记录无法配准、覆盖不足和人工拒绝的样本，而非只报告成功样本。

Windows 上请使用短且唯一的 pytest `basetemp`。过深临时路径会触发现有 CAD 工件完整性失败；这是环境路径深度诊断，不应通过放宽产品阈值或重写历史工件来掩盖。
